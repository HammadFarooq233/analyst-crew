# Phase 0 Issue 3: Planner Agent with real OpenRouter LLM

## Parent

`docs/prd-phase-0-walking-skeleton.md`

## What to build

Swap the stub Planner node for a real LLM call. The Planner Agent uses an OpenRouter free model (`google/gemma-4-26b-a4b-it:free`) via LangChain's OpenAI-compatible `ChatOpenAI` client, with structured output parsing into the `Plan` Pydantic model defined in Issue 002.

The Planner's system prompt defines the Agent's role: decompose a user's analytical question into an ordered Plan of Steps, each naming a target Agent (Fetcher, Analyst, Visualizer, Critic, Reporter), what each Step produces, and which prior Steps it depends on. The prompt instructs the Planner to consider data sources, analysis methods, and verification steps. At this stage, there is no memory tool — the Planner works purely from the user question.

The `planner_node` extracts the user question from `state["messages"]`, invokes the LLM with the system prompt and structured output parser, and stores the resulting `Plan` at `state["artifacts"]["plan"]`.

The OpenRouter API key is loaded from environment (`.env`) via the config module — never hardcoded or committed. If the API key is missing or the free-model rate limit is exceeded, the CLI surfaces a clear error message.

## Acceptance criteria

- [ ] `PlannerAgent` class or module that constructs the system prompt and calls OpenRouter via `ChatOpenAI`
- [ ] System prompt instructs the model to produce a Plan with Steps naming real Agents, produces descriptions, and dependency ordering
- [ ] LLM response is parsed via `with_structured_output(Plan)` into the Pydantic model
- [ ] `graph.invoke()` with a real user question returns a `CrewState` with a `Plan` generated by an OpenRouter free model
- [ ] The Plan is valid per the Pydantic schema (correct Step types, no circular dependencies, ≥1 Step)
- [ ] `cli.py` prints the real Plan — same interface as Issue 002, now backed by a real LLM
- [ ] Missing or invalid `OPENROUTER_API_KEY` produces a clear error message, not a cryptic stack trace
- [ ] Test: `test_planner.py::test_llm_plan_valid` invokes the graph with a fixed question and asserts the Plan is a valid Pydantic model (tests may be skipped in CI due to API dependency; marked with `@pytest.mark.llm`)
