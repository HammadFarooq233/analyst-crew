# Domain Docs

This is a single-context repository.

Before exploring or changing the Crew, read the root `CONTEXT.md` and relevant ADRs under `docs/adr/`. Use glossary vocabulary in specs, issues, tests, and implementation. Surface conflicts with an accepted ADR explicitly rather than silently overriding it.

Domain terms and decisions are documented lazily as they are resolved. Do not create speculative glossary entries or ADRs before a real ambiguity is settled.
